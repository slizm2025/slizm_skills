# 知识文档结构模板

模板提供组织方式，不是强制章节清单。选择最接近的类型，删除空章节，并按读者的学习顺序调整。不要为了完整外观制造会话中没有的内容。

## 1. 通用学习笔记模板

适用于语言特性、框架机制、工具概念、算法、业务方法等可迁移知识。

```markdown
# <主题>学习梳理

> 一句话说明本文解决什么学习问题，以及适合什么基础的读者。

## 1. 一句话定位

<这组知识是什么，能解决什么问题。>

## 2. 整体地图

```text
<概念 A>
  -> <过程或关系 B>
  -> <结果 C>
```

<用一小段解释地图，不在这里展开所有细节。>

## 3. 必要前置知识

<只解释后文确实依赖的基础；没有则删除本节。>

## 4. 核心知识

### 4.1 <概念一>

- **是什么**：
- **如何工作**：
- **何时使用**：
- **边界或易错点**：

```<language>
<最小、自洽的例子>
```

### 4.2 <概念二>

<避免重复解释概念一，只说明关系或差异。>

## 5. 贯穿示例

<使用一个例子展示多个知识点怎样协作。先给输入和目标，再逐步说明变化，最后给结果。>

## 6. 易混概念

| 概念 A | 概念 B | 核心区别 | 选择依据 |
|---|---|---|---|
| ... | ... | ... | ... |

## 7. 常见误区与边界

1. **误区**：...
   **正确理解**：...
2. ...

## 8. 速查

| 想完成的目标 | 使用的概念或操作 | 关键条件 |
|---|---|---|
| ... | ... | ... |

## 9. 最终记忆主线

```text
<用 3～7 个节点压缩全文关系>
```

### 必记要点

1. ...
2. ...
3. ...

## 10. 自测问题

1. ...？
2. ...？
3. ...？
```

### 裁剪规则

- 内容少时保留：定位、整体地图、核心知识、一个示例、必记要点。
- 没有易混概念时删除对比表。
- 速查和记忆主线不得完整复述核心知识。
- 自测题应检验理解和迁移，不只让读者背定义。

## 2. 项目知识说明模板

适用于用户明确要求理解或复现某个项目、页面、模块或业务链路。

```markdown
# <项目或功能>知识说明

> 分析范围：<项目/模块/版本基线>
> 证据边界：<当前代码、文档、环境待确认项>

## 1. 结论与适用范围

<一句话定位、覆盖内容、不覆盖内容。>

## 2. 系统地图

```text
<入口>
  -> <组件或服务>
  -> <数据/外部依赖>
  -> <可观察结果>
```

## 3. 模块职责

| 模块 | 职责 | 输入 | 输出 |
|---|---|---|---|
| ... | ... | ... | ... |

## 4. 核心调用链或数据流

<按入口到结果解释，不逐文件罗列。>

## 5. 项目特有规则

<状态机、公式、权限、时间窗、错误策略等。明确标记为当前实现。>

## 6. 可迁移的通用知识

<从项目中抽取可用于其他系统的概念和方法，与项目事实分开。>

## 7. 已知限制、风险与待确认项

| 类型 | 当前事实 | 影响 | 建议核验方式 |
|---|---|---|---|
| ... | ... | ... | ... |

## 8. 复现或验证路径

<仅在用户需要复现时保留。包含前置条件、步骤、验证和失败处理。>

## 9. 关键代码导航

| 目标 | 文件或符号 | 说明 |
|---|---|---|
| ... | ... | ... |

## 10. 最终记忆主线

<压缩项目主链，不重复所有模块清单。>
```

### 项目型文档规则

- 写明代码、分支、commit 或时间基线；不能证明的环境信息标“待确认”。
- “当前实现”和“推荐设计”必须分开。
- 通用学习知识单列，不让路径、表名和业务编码淹没概念。
- 不复述密钥和隐私数据。
- 只有用户要求部署或复现时才加入大量命令。

## 3. 问题复盘模板

适用于 bug、合并冲突、事故、失败测试和性能回归。

```markdown
# <问题主题>复盘

## 1. 问题摘要

- 现象：
- 影响：
- 发生条件：
- 当前结论：

## 2. 正常流程与故障点

```text
<正常链路>
              X <实际故障点>
```

## 3. 根因

### 直接原因
<最接近故障的技术原因。>

### 深层原因
<流程、测试、接口边界、并发或认知问题。没有证据则标记待确认。>

## 4. 处理方案

<说明为什么选择该方案，以及没有选择其他方案的条件。>

## 5. 修复与验证

| 步骤 | 操作 | 预期信号 | 实际结果 |
|---|---|---|---|
| ... | ... | ... | ... |

## 6. 风险与恢复方式

<高影响操作、备份、回滚或 abort 条件。>

## 7. 可迁移知识

<把个案提炼成一般诊断方法、Git 语义、测试原则等。>

## 8. 预防措施

<测试、检查清单、流程或监控。区分已实施与建议。>

## 9. 记住这几点

1. ...
2. ...
```

### 复盘规则

- 时间线只保留理解因果所需的节点。
- commit、分支和路径作为证据，不要让它们替代原理解释。
- Git 冲突标记消失只说明文本冲突已处理，不证明业务语义正确。
- 对危险命令写清执行前检查和恢复方法。

## 4. 操作手册模板

适用于可重复执行的 Git、部署、迁移、配置和人工处理流程。

```markdown
# <操作目标>手册

## 1. 目标与适用范围

<要达到的状态，以及不适用的情况。>

## 2. 前置条件

- 权限：
- 环境：
- 输入或备份：
- 当前状态检查：

## 3. 流程总览

```text
检查 -> 执行 -> 验证 -> 成功结束
              -> 失败处理/回滚
```

## 4. 操作步骤

### 步骤 1：<名称>

```<language>
<命令或配置>
```

- 作用：
- 成功信号：
- 失败时：

## 5. 最终验证

<用可观察信号确认结果，而不是只写“执行成功”。>

## 6. 风险与回滚

| 操作 | 影响 | 执行前检查 | 恢复方式 |
|---|---|---|---|
| ... | ... | ... | ... |

## 7. 常见问题

### <现象>
- 原因：
- 处理：
```

### 操作手册规则

- 只读检查放在变更操作之前。
- 删除、覆盖、强制推送、生产迁移等操作必须突出影响。
- 不把某次机器上的绝对路径写成通用前提，使用占位符并给出替换说明。
- 步骤应幂等或说明重复执行的后果。

## 5. 多主题知识集模板

适用于 Git、Vue、Java、测试等多个无依赖主题同时出现的会话。

### `README.md`

```markdown
# <知识集名称>

## 1. 收录范围

<说明来源范围和拆分原则。>

## 2. 知识地图

```text
基础主题 A -> 进阶主题 B
独立主题 C
问题复盘 D
```

## 3. 阅读顺序

| 顺序 | 文档 | 适合读者 | 前置知识 |
|---:|---|---|---|
| 1 | [主题 A](./主题-A.md) | ... | 无 |
| 2 | [主题 B](./主题-B.md) | ... | 主题 A |
| - | [主题 C](./主题-C.md) | ... | 可独立阅读 |

## 4. 跨主题共同原则

<只有真正共用的原则才写在这里，不复制各文档正文。>
```

每个主题文件选择前述最适合的模板。一个概念只指定一个权威解释文件，其他文件用链接引用。

## 6. 更新已有文档的编辑模板

更新不是在文末追加新答案。执行以下顺序：

```text
读取全文
  -> 标记主题和重复章节
  -> 找到元文本、坏围栏和范围漂移
  -> 选择每个概念的主解释位置
  -> 合并新增知识
  -> 删除重复或过时内容
  -> 重建目录和记忆主线
  -> 完整性与 Markdown 检查
```

保留原文中已经清楚、准确、有教学价值的段落。只有在结构或准确性需要时才重写，避免为了统一措辞而无意义改写全文。
