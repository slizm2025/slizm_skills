# 总结会话知识点

把会话中值得长期保留的内容重新组织为一份**不依赖原会话、不依赖原项目也能理解**的知识文档。目标不是压缩聊天记录，而是完成一次编辑、归纳和教学重构。

## 核心质量标准

成品同时满足以下要求：

1. **完整**：当前可见会话及用户指定材料中的有效知识均已覆盖，或明确说明无法访问的范围。
2. **去重**：一个规范概念只有一个主解释位置，其他位置只引用或补充新边界。
3. **隔离**：不同主题、不同抽象层级和不同事实类型不混写。
4. **独立**：首次接触该主题、未看过原会话和原项目的读者也能顺序学习。
5. **准确**：不把项目事实泛化成普遍规律，不把猜测包装成事实。
6. **纯净**：正文不包含代理思考、工具过程、权限说明、交付话术或聊天残片。
7. **可复习**：有整体地图、关键区别、记忆主线；内容合适时增加速查和自测。

## 输入与边界

可使用的输入包括：

- 当前可见会话中的用户问题、解释、结论、代码片段、案例和纠正；
- 用户明确指定的本地文档、附件或代码；
- 为核验知识而实际读取的一手资料。

遵守以下边界：

- “会话中的所有知识点”仅指当前上下文中实际可见、可读取或可检索的内容。不得假装读取了已丢失的历史消息。
- 如果用户给出目标文件，先读取已有文件再决定补充、重构或新建；来源不明的同名文件不直接覆盖。
- 用户只要对话输出时不创建文件；用户要求保存但未指定名称时，使用能表达主题的 Markdown 文件名。
- 默认只改知识文档，不修改业务代码、配置或测试。
- 不把为了完成任务而临时获得的工具知识自动写入正文，除非它本身就是用户要学习的主题。

## 先判断文档类型

根据内容选择最合适的产物，不要用一套模板硬套所有会话：

| 类型 | 适用场景 | 默认重点 |
|---|---|---|
| 通用学习笔记 | 学习概念、语言、框架、工具或方法 | 原理、关系、示例、易错点、自测 |
| 项目知识说明 | 理解特定系统或功能实现 | 边界、调用链、项目规则、代码导航、限制 |
| 问题复盘 | 调试、事故、冲突或性能问题 | 现象、根因、修复、验证、预防、可迁移经验 |
| 操作手册 | 需要重复执行的流程 | 前置条件、步骤、验证、失败处理、回滚、风险 |
| 多主题知识集 | 会话横跨多个彼此独立的主题 | 主题索引与独立篇章，避免按聊天顺序拼接 |

若用户明确指定文档类型，服从用户要求。否则优先生成通用学习笔记；只有项目身份和实现细节本身具有学习价值时才生成项目知识说明。

在开始组织正文前，读取并执行：

- [内容筛选、去重与隔离协议](references/content-selection-protocol.md)
- [知识文档结构模板](references/knowledge-document-template.md)

## 工作流

### 1. 建立总结范围

确定：

- 知识主题与预期读者；
- 输入来源及实际可访问范围；
- 输出文件、更新方式和文档类型；
- 是否需要保留项目复盘、代码导航或操作步骤。

仅当答案会改变主题边界、文件覆盖方式或文档类型时询问用户。可以从上下文和指定文件确定的内容不重复提问。

### 2. 提取候选知识点

先完整扫描输入，再组织文档。提取：

- 概念、术语和定义；
- 原理、机制、数据流和调用关系；
- 方法、步骤、命令与适用条件；
- 对比、边界、反例和常见误区；
- 公式、状态机、约束和安全注意事项；
- 会话中对先前说法的纠正或限定；
- 有教学价值的案例和验证方法。

不要把问答轮次当作章节。用户问了三次同一概念，只产生一个候选知识点，并吸收后续新增的信息。

### 3. 主题聚类与知识点归一化

为每个候选知识点建立内部规范名称和稳定含义，例如：

```text
K-001：Stream 的惰性执行
K-002：中间操作与终止操作
K-003：Lambda 的目标类型推断
```

这些 ID 只用于内部整理，默认不写入成品。

按“读者学习时需要先知道什么”排序，而不是按消息时间排序。将相邻知识合成学习主线，将无依赖的主题拆开。区分：

- 同义重复：合并；
- 同一概念的新边界：补入主解释；
- 相关但不同的概念：分别解释并建立关系；
- 表面相似但语义不同的术语：放入“易混概念”，不得错误合并。

### 4. 分离通用知识、示例和项目事实

每条内容放入以下一层：

1. **通用层**：脱离项目仍成立的定义、机制和方法；
2. **示例层**：用于解释通用知识的中性或项目示例；
3. **项目事实层**：只对特定仓库、版本、业务或环境成立的事实。

默认正文以通用层为主。项目名称、绝对路径、类名、接口地址、分支、提交哈希、业务编码和人员角色只有在以下情况才保留：

- 用户明确要求项目实现报告或问题复盘；
- 它是理解调用链、验证结论或复现问题所必需的证据；
- 它被清楚标记为“项目示例”“当前实现”或“适用范围”，不会被误读为普遍规律。

否则将项目对象换成中性例子。例如把某项目的 `DailyCostPoint` 改写为普通的 `Order`、`Product` 或数字列表；项目原例确有价值时可在通用解释后单独保留。

### 5. 组织教学结构

先写主干，再补细节：

1. 一句话说明这组知识解决什么问题；
2. 给出整体地图、数据流或概念关系；
3. 解释核心概念及其输入、输出、条件和边界；
4. 使用一个贯穿示例串起抽象概念；
5. 区分易混概念和常见误区；
6. 最后给出压缩后的速查、记忆主线和自测。

遵循“先使用后原理、先整体后局部、首次出现先解释”的原则。术语在第一次出现时解释清楚，后文直接使用。

不要机械填满模板。小主题可只保留“定位、核心知识、示例、记忆点”；没有真实内容的章节直接删除。

### 6. 处理多主题会话

不同主题之间存在学习依赖时，在一个文档中分成独立篇章，并在开头给出知识地图。

满足以下任一情况时，优先拆成多个文件并生成总索引：

- 主题属于不同技术领域，且彼此没有前置依赖；
- 任一主题已经可以独立形成较完整的学习文档；
- 合并后会迫使读者在 Git、Vue、测试、业务实现等无关内容之间跳转；
- 用户明确要求“做好知识点隔离”。

拆分后仍要检查跨文件重复：公共概念放在最合适的主文档，其他文档通过链接引用，不复制整段解释。

### 7. 清理对话元文本

知识正文不得包含：

- `The user wants me...`、`Wait...`、`thinking`、`深度思考` 等内部推理或模型自述；
- “用户要求……”“让我先……”“我接下来会……”等任务过程；
- 工具调用、权限模式、记忆检查、token 或上下文管理说明；
- “我无法创建文件”“请复制以下内容到桌面”等交付话术；
- 与知识无关的执行状态、任务清单和下一步聊天提示；
- 完整文档外又嵌套一层用于复制的 Markdown 围栏；
- 依赖聊天现场的“上面这段”“如前所述”“你的方案”等无明确指代文本。

允许中性的来源或范围说明，例如“本文整理 Java Stream 的核心概念”，但读者不得需要回看对话才能理解正文。

### 8. 控制真实性、时效性与安全性

- 会话中存在纠正时，以最后经证据支持的结论为准，并保留必要的适用条件。
- 无法核验的内容标记为“待确认”“经验建议”或“项目约定”，不得写成确定事实或无条件最佳实践。
- “推荐做法”必须说明适用前提和替代方案，尤其不能把某团队的临时分支策略泛化为行业标准。
- 对 `git clean -fd`、强制推送、删除分支、覆盖文件、生产迁移等高影响操作，写明影响、前置检查、安全替代和恢复路径。
- 项目型文档注明代码或版本基线；通用文档避免加入会迅速过期的提交哈希和环境状态。
- 不复述密钥、token、密码或其他秘密；只说明应使用安全配置或秘密管理。

### 9. 写入或更新文档

更新已有文档时：

1. 保留仍正确且组织良好的内容；
2. 合并重复章节，不在文末简单追加另一份总结；
3. 删除误入的模型思考、聊天话术、坏掉的围栏和重复正文；
4. 修正范围漂移、错误泛化和过时结论；
5. 维持原文合理的标题层级、术语和示例风格。

新建文档时，使用 [知识文档结构模板](references/knowledge-document-template.md) 中最接近的结构并按事实裁剪。

### 10. 最终自检

交付前逐项检查：

- 是否覆盖了所有有效候选知识点？遗漏项是否有明确原因？
- 未看过原会话和项目的人能否从头理解？
- 每个核心概念是否只有一个主解释位置？
- 速查和总结是否只是压缩，而不是重新讲一遍全文？
- 通用知识、示例和项目事实是否分层？
- 是否把项目约定、推测或个案错误写成普遍规律？
- 是否混入代理思考、工具过程、权限说明或交付话术？
- 不同主题是否已隔离，是否需要拆成多个文件？
- 代码围栏、表格、标题层级和内部链接是否完整？
- 命令和操作是否说明风险、前提与验证？
- 不确定项、时效边界和无法访问的来源是否如实披露？

若删除某段后不影响理解主线、关键边界或实践能力，优先删除或合并。

## 最终回复

简要报告：

```text
执行结果：完成 / 部分完成 / 需要补充材料
- 文档类型：
- 输入范围：
- 输出文件：
- 主题及拆分结果：
- 已执行处理：知识提取、去重、项目解耦、元文本清理、结构重组
- 证据或时效边界：无 / 列表
- 未覆盖内容：无 / 列表及原因
```

不要在最终回复中重新粘贴整份文档。不得声称读取了未访问的历史会话、文件或代码。
